# CTEA Sketch Ivory 美術規範

本文件定義現行 CTEA homepage 的視覺與互動系統，對齊 `ctea-homepage` 實作（`styles.css`、導覽、hero carousel、landing 區塊）。建構或調整頁面時，請以此為依據。

整體體驗應呈現正式馬術協會透過象牙色紀念刊物所傳達的質感：具機構感、紀律感、開闊感，以及低調的精品感。同時允許現代運動能量——以無襯線展示字與精簡拉丁字標強化可讀性與競賽節奏。不得偏離為泛用精品品牌、鄉村馬術風格、儀表板式產品介面，或過度卡片堆疊。

實作參考：

- Token／字級：`src/styles.css`
- 導覽：`src/components/top-nav-bar/`
- Hero：`src/components/hero-carousel/`
- 首頁區塊：`src/routes/-component/landing-content.tsx`

## 文件定位與使用方式

- 本文件是視覺方向與驗收依據；`src/styles.css` 是色彩、字體與尺寸 token 的技術唯一來源。兩者不一致時，先確認設計意圖，再同步修正文件與實作，勿讓兩套規則並存。
- 規則優先序為：**核心方向與避免事項 → 共用 token → 元件模式 → 單頁例外**。單頁例外必須有內容或功能理由，不得只為追求新鮮感。
- 文件中的 Tailwind class 與數值是現行 recipe，不是不可更動的品牌本質。重構時可更換寫法，但視覺角色、比例與互動結果需保持一致。
- 新頁面先選擇適合的區塊性格與既有模式，再組合版面；勿直接複製整段首頁構圖。
- 本規範目前以公開網站與首頁體驗為主要範圍，不涵蓋後台 CMS 介面。

## 核心方向

- 結合國家級體育機構的權威感與編輯刊物的精緻感，並以現代無襯線展示字帶出競賽清晰度。
- 以影像、字體角色、細線與留白作為主要設計素材。
- 馬術與建築母題應作為身分證據，而非裝飾性壁紙。
- 構圖保持沉穩、有意圖。每個區塊只傳達一個主要訊息。
- 精品質感來自比例、克制、裁切紀律與字體角色分工，而非光澤、模糊或過度裝飾。
- 維持攝影寫實（hero／影像區）與紙本機構敘事（編輯區塊、素描底紋）之間的張力。
- 淺色為預設世界觀；深色模式為同等一等公民，需同步設計。

### 用色規則

- 純白過於現代、冰冷；純黑過於嚴厲。Hero 可用近白 `#fffaf0` 與深色 scrim，編輯區仍以暖象牙／近墨為主。
- 海軍藍可用於受控的全幅權威區塊（影音、頁尾），不作每個區塊的預設底色。
- 金色是結構性標點與強調；大面積填金僅限小控制項作用態（如篩選 chip），勿作整區底。
- 淺／深模式都必須維持足夠對比與同一套金／海軍藍權威語言。
- 避免亮金屬金、冷灰產品 UI、飽和藍、祖母綠、紅色強調、霓虹色與強烈多色漸層。



## 字體規則

字體以 `styles.css` 的角色對照表為準。元件應組合「一個字體角色 + 一個字級角色」，例如 `font-display text-hero`。

### 字體角色


| 角色          | 堆疊                                                | 用途                    |
| ----------- | ------------------------------------------------- | --------------------- |
| **brand**   | `Songti TC`, `PMingLiU`, ui-serif, Georgia, serif | 僅協會中文名                |
| **display** | `PingFang TC`, `Microsoft JhengHei`, sans-serif   | Hero／區塊中文大標           |
| **body**    | 同上無襯線                                             | 導覽、內文、控制項、按鈕標籤        |
| **sport**   | `Barlow Condensed` + CJK sans                     | 英文 kicker、日期、編號、英文品牌行 |


載入字型：Barlow Condensed 600／700（self-hosted）；CJK 使用系統字。

### 字級角色（token）

- **text-hero：** `clamp(2.5rem, 6vw, 6rem)`，行高 `1.08`，字距 `0.02em`，字重 `700`
- **text-section：** `clamp(2.125rem, 4vw, 3.75rem)`，行高 `1.15`，字距 `0.035em`，字重 `700`
- **text-feature-title：** `clamp(1.5rem, 2.25vw, 2.25rem)`，字重 `700`
- **text-card-title：** `1.25rem`，字重 `700`
- **text-lead：** `clamp(1rem, 1.25vw, 1.1875rem)`，行高 `1.75`
- **text-body / text-body-sm：** `1rem` / `0.875rem`，行高約 `1.7-1.75`
- **text-brand：** `clamp(1rem, 2vw, 1.8125rem)`，字距 `0.08em`，字重 `700`
- **text-nav：** `clamp(0.9375rem, 1.15vw, 1.25rem)`，字距 `0.04em`，字重 `700`
- **text-action：** `0.875rem`，字距 `0.07em`，字重 `700`
- **text-meta：** `0.8125rem`，字距 `0.055em`
- **text-kicker：** `0.75rem`，字距 `0.16em`，字重 `700`，通常大寫
- **text-overline：** `0.6875rem`，字距 `0.12em`，字重 `700`



### 排版習慣

- 區塊標題模式：英文 sport kicker → 中文 display 標題 → 英文 sport meta。
- Hero 標題可刻意兩行；第二行可用 Hero 金強調。
- 長篇內文維持較窄編輯欄與舒適行高；勿在元件中散落一次性字級。
- 避免書法體、斜體精品手寫、幾何展示字、過重多層陰影字效。



## 間距規則

- 細部節奏採 `4px / 8px`；區塊垂直常用 `py-24 md:py-32 lg:py-36`（約 `96 / 128 / 144px`）。
- 水平邊距：內容區常 `px-5 md:px-10 lg:px-16`；頁首參考 `px-11`／`px-7`／`px-4`。
- 互動目標至少約 `44px`（`min-h-11`）；導覽連結約 `min-h-12`；Hero CTA 約 `min-h-13`。
- 主要內容群組周圍應有明顯呼吸空間。勿以裝飾內容填補空白。
- Hero 文案階層參考：kicker 線 → 標題 `mt-6` → 說明 `mt-5` → CTA `mt-7`。
- 細線可組織內容；必要時才使用邊框面板（如社群 embed）。



## 版面原則



### Hero 結構

- 全幅攝影輪播，高度約 `100dvh - header`。
- 左側編輯文案疊於深色 scrim 之上；非紙面分割主視覺。
- 桌面 scrim：左／下方向漸層；行動改底部較強漸層（約高度 `84%`）。
- 內容最大寬約 `1600px`；文案欄約 `max-w-220`。
- 底部控制列：上一張／進度指示／下一張／播放暫停。



### 後續區塊

- 採不對稱編輯構圖；分割區避免無理由的 `50 / 50`。
- 桌面仍以 12 欄心智模型規劃（如新聞主欄 `col-span-7`）。
- 控制文字行寬：展示約 `max-w-3xl` 級、內文 `max-w-2xl`、窄輔助 `max-w-sm`／`max-w-md`。
- 影像可偶用 `clip-path`（如橢圓裁切）整合紙面，曲線應寬廣、具建築感。
- 活動列表以橫列、日期與細分隔線為主；社群 embed 可使用低對比邊框面板，但勿擴散成 bento／儀表板。



### 避免

- Bento 格線、浮動玻璃行銷面板、藥丸形主導航、儀表板版面。
- 每個區塊重複相同構圖。
- 密集圖示集合、大圓角或過重陰影。
- 預設將每個區塊置中。



## 影像處理

- 攝影應正式、有紀律；編輯區在暖紙環境中略為柔化，Hero 則以深色 scrim 保證可讀。
- 優先盛裝舞步、競賽、訓練、場館建築、傳承場地、儀式細節與受控動作。
- 裁切時保留臉部、馬頭、姿態、馬具與機構標誌。
- Hero 使用 `object-fit: cover`，並以每張投影片的 `imagePosition` 設定焦點，勿一律置中。
- 背景素描圖稿應保持可見、低對比；勿以不透明面板完全覆蓋。
- 配對影像時匹配暖度、對比與正式感。
- 避免生硬去背、飽和運動攝影、冷色電影調、侵略性放大裁切與任意雙色調。

### 影像驗收

- **可接受：** 主體動作與視線清楚、馬匹比例完整、背景能交代場地或競賽脈絡、色溫自然偏暖、暗部仍保留細節。
- **不可接受：** 馬頭或騎手關節被無意裁斷、文字壓住臉部／標誌、為配合版面而水平翻轉含文字或徽章的照片、套用高飽和濾鏡掩蓋素材差異。
- 同一畫面若使用多張照片，應先統一曝光、白平衡與黑位，再考慮裝飾性處理。
- 每張關鍵影像都應記錄寬螢幕與行動版焦點；若同一裁切無法同時成立，使用不同 `imagePosition` 或 art direction 素材。

### 視覺基準畫面

每次改動全域 token、導覽、Hero 或共用區塊後，至少比對下列四個基準狀態：

| 模式 | 寬度 | 驗收重點 |
| --- | ---: | --- |
| 淺色桌面 | `1440px` | 導覽比例、Hero 焦點、象牙色溫、區塊留白 |
| 深色桌面 | `1440px` | 文字對比、金線亮度、深色面板層次 |
| 淺色行動版 | `375px` | 品牌字標、Hero 底部文案、觸控目標、無橫向捲動 |
| 深色行動版 | `375px` | 選單表面、焦點狀態、影像與 scrim 可讀性 |

另以 `320px` 做壓力測試；它是容錯下限，不是主要構圖基準。



## 動態規則

動態應強化結構方向：輪播落定、進度推進、導覽底線，而非介面元素向上淡入堆疊。

### Hero 動態

- 投影片交叉淡入：約 `400ms`。
- 作用中影像由 `scale(1.025)` 收斂至 `scale(1)`，時長 `8s`，緩動 `cubic-bezier(0.16, 1, 0.3, 1)`（僅作用中投影片一次，非無限呼吸循環）。
- 文案自右側約 `18px` 橫移並淡入：進場約 `360ms`（延遲約 `100ms`）。
- 進度條以 `scaleX` 推進，自動播放週期 `7000ms`。
- 懸停或焦點在 carousel 內時應暫停自動播放邏輯（由容器狀態控制）。



### 時間與緩動

- 主要緩動：`cubic-bezier(0.16, 1, 0.3, 1)`。
- 懸停過渡：通常 `180-320ms`（多為 `200ms`）。
- 僅動畫化 transform、opacity，以及必要的 border／background color。
- 勿加入彈跳、彈性過衝、捲動劫持、大幅視差或整頁背景無限漂移。



### 互動動態

- 導覽底線自中央以 `scaleX` 展開。
- Hero CTA：背景填金、文字轉深；箭可不大幅位移（約 `0.5` 單位）。
- 行動選單兩條線旋轉為關閉符號。
- 主題切換控制維持方形金邊，無位移縮放。



### 減少動態

- 必須尊重 `prefers-reduced-motion: reduce`／`motion-reduce:`。
- 減少動態時顯示完整最終構圖；移除長時縮放、進場延遲與裝飾性位移。
- 勿依賴動畫傳達必要狀態；自動播放應可暫停。

## 可及性與互動狀態

- 一般文字與背景對比至少符合 WCAG AA `4.5:1`；大字至少 `3:1`。金色不可在暖象牙底上承擔小字長篇閱讀。
- 所有互動元素需可用鍵盤到達，並具可見的 `:focus-visible`；焦點不可只以細微色差表示。
- Hover 才出現的資訊，也必須能在 focus、觸控或展開狀態取得。
- 輪播需提供上一張、下一張與暫停；使用者操作後不得無預警搶回焦點。狀態與目前張數應有可理解的無障礙名稱。
- 圖示按鈕必須有可辨識名稱；純裝飾圖形使用 `aria-hidden="true"`。
- 錯誤、成功、選中與停用狀態不可只靠顏色辨識，需搭配文字、圖示、線條或其他結構提示。
- 觸控目標以 `44 × 44px` 為最低標準；相鄰小控制項需保留足夠間距。
- 內容與控制項在 `200%` 縮放、鍵盤操作及 `prefers-reduced-motion` 下仍需完整可用。



## 按鈕與行動樣式



### Hero 主 CTA

- 形狀：直角矩形。
- 邊框：`1px` `#d0ae6d`；底 `rgba(9,23,37,.62)` + 輕微 `backdrop-blur`。
- 標籤：`font-body text-action`，`#fffaf0`。
- 最小高度約 `52px`（`min-h-13`），行動略減。
- Hover：填 `#d0ae6d`，文字 `#091725`。
- Focus：可見金／象牙 outline，offset 寬裕。
- 勿整體位移、縮放、彈跳或光澤掃過。



### 編輯區次要行動

- 襯線並非必要；使用 `font-body text-action` 文字連結 + 金色底線。
- Hover 轉向標語金；深色模式用較亮金。
- 方框圖示鈕：金邊透明底，hover 可填海軍藍。
- 每區塊維持一個主導行動。
- 避免藥丸形、大圓角、漸層填色與亮金大按鈕作為預設主行動。



## 導覽樣式

- 導覽是正式頁首，不是應用程式工具列。
- 表面：半透明暖象牙 + 底部古金細線 + 克制暖陰影與輕 `backdrop-blur`。
- 高度 token：桌面 `122px`、`<64rem` 為 `96px`、`<40rem` 為 `82px`。
- 品牌群組置左：徽章、中文 `font-brand`、英文 `font-sport` 大寫行。
- 桌面連結均勻分布，短垂直金細線分隔；`font-body text-nav`。
- Hover：標籤轉標語金，底線自中央展開。
- 右側含主題切換（淺／深）；大斷點以下改行動選單。
- 避免實心作用中分頁、粗底線、背景藥丸與慣例黑色固定列。



### 固定導覽

- 頁首固定於頂部；捲動隱藏／顯示可使用 translate，但不改變視覺語言。
- 保留金色底線；模糊與陰影保持克制。



### 行動導覽

- 以約 `36px`（`size-9`）方形選單控制搭配兩條細橫線；開啟時旋轉為關閉符號。
- 選單：暖象牙／深色面板、細金邊框、克制陰影。
- 項目：`font-body text-nav` + 水平分隔線，`min-h-12`。



## 深色模式規則

- 主題切換置於頁首，狀態需可辨識（`aria-pressed`）。
- 所有新區塊必須同時提供淺／深樣式，不可只做淺色再反相。
- 深色模式仍使用金線與海軍藍權威色，而非改走冷灰產品風。
- Hero 本身已是深色攝影舞台，不因主題切換重構為紙面主視覺。



## 行動裝置適配規則

- 主要結構斷點：導覽約 `lg`；區塊堆疊多在 `md`。
- 圖文分割改為垂直序列時，優先保留影像焦點主體。
- Hero 行動版文案靠下對齊，scrim 改底部可讀性優先。
- 先縮減字距與邊距，再縮小至難以閱讀的字級。
- 維持至少約 `44px` 觸控目標。
- 在 `320px`、`375px` 與平板寬度測試。單字孤行、字標裁切或橫向捲動皆不可接受。
- 勿以堆疊行銷卡片或簡化泛用橫幅取代構圖。

## 功能性元件模式

- **表單：** 標籤固定顯示，不以 placeholder 取代；輸入框使用紙面／細線語言，錯誤訊息緊鄰欄位並明確說明修正方式。
- **表格：** 保留清楚欄名與列分隔；行動版優先允許受控橫向捲動或改為定義列表，不壓縮至難以閱讀。
- **手風琴：** 使用細分隔線與清楚的展開圖示；整列標題皆可操作，並公開 `aria-expanded` 狀態。
- **下載：** 以文件名稱、格式、檔案大小／日期與單一下載行動組成橫列；避免為每份文件建立大型卡片。
- **長文／CMS 內容：** 限制閱讀行寬，提供一致的標題、清單、引文、表格、連結與圖片說明樣式；不可讓 CMS 任意顏色覆蓋品牌 token。
- **載入、空白與錯誤：** 優先使用排版、細線與簡潔文字說明；避免用大型插圖或擬產品式 skeleton 破壞機構語氣。
- **停用狀態：** 降低強調但保持可讀；若使用者需要知道原因，應就近說明，不只降低 opacity。



## 後續區塊性格

後續區塊應像同一本紀念協會刊物的章節，並沿用字體角色與金線節奏。

- **活動與行事曆：** 精確、有序。日期與橫列、篩選作用態可用標語金、報名／強調可用海軍藍。
- **關於與歷史：** 檔案感與編輯感。寬幅影像搭配窄文字欄、引文、里程碑。
- **馬術教育：** 清晰、教學性，避免企業感。紀律圖解、節制列表、真實訓練攝影。
- **治理與制度：** 正式、易讀。表格或手風琴 + 紙面／深色面板與細邊框。
- **會員：** 歡迎但仍具機構感。受控海軍藍行動區、排版欄權益、極簡線條圖示。
- **下載：** 功能性、低調。文件以線條橫列呈現，而非大卡片。
- **社群：** 允許低對比邊框 embed 面板；保持克制陰影，勿擴成卡片牆。
- **頁尾：** 儀式性收尾。暖象牙介紹 + 海軍藍資訊區、徽章、精簡協會資訊與細金分隔線。

全頁應在影像主導、文字編輯與功能性資訊之間維持節制節奏。網站在 Hero 之下應更實用，同時不失去紀律、傳承與視覺沉靜。

## 品質檢核

- 區塊是否有單一明確焦點？
- 是否使用正確字體／字級角色，而非一次性堆疊？
- 攝影裁切是否以主體為依據，而非預設置中？
- 金色與海軍藍是否節制且具權威感？
- 淺色與深色是否都完整且對比足夠？
- 細線或留白能否取代不必要的卡片？
- Hero／導覽動態是否遵循既定語言？
- 啟用減少動態時，最終狀態是否完整？
- 行動版是否保留層級與主體焦點？
- 區塊是否像馬術機構，而非泛用精品品牌或產品儀表板？
- 是否涵蓋 hover、focus、active、disabled、loading、empty 與 error 等相關狀態？
- 是否通過四個視覺基準畫面與 `320px` 壓力測試？
